# Список solution для графа скиллов: Angular-приложение

Структура графа: solution → plateau → class/projects/sln (по аналогии с dotnet core backend).
Ниже — список solution-кандидатов с текущим статусом решения. Пункты сгруппированы по смысловым блокам, но в графе это плоский список решений с зависимостями друг от друга.

Отдельно отмечен паттерн, который встретился несколько раз в этом списке:
**база + расширение** — сначала фиксируется базовое solution, затем отдельное solution-расширение добавляет новую возможность/plateau поверх базы, не переписывая её. Встречается в: структура репо → встраиваемость; структура репо → offline-first; routing → lazy loading; логирование база → логирование с отправкой на бэк.

## 2. Данные и состояние

| # | Solution | Статус | Заметки |
|---|----------|--------|---------|
| 4 | **State management** | Решено (подход) | Трёхуровневая политика: Angular Signals — component-local state; NgRx Signal Store — feature-level state; классический NgRx Store (actions/effects) — глобальный/cross-cutting state (auth, notifications, offline-sync) |
| 5 | **API/HTTP-слой** | Open | Текущий паттерн: Facade → NgRx event → CustomClient (DTO mapping) → HttpClient + interceptors. Требует пересмотра — отдельное solution с обсуждением подхода |
| 6 | **Offline-first** | Решено (подход) | Расширение над #1 (структура репо), не отдельная ветка с нуля. PWA offline-first с синхронизацией данных |
| 7 | **Синхронизация offline-данных** | Open | Свой sync-слой vs готовая библиотека (RxDB/WatermelonDB и т.п.) — не решено |

## 6. Дизайн-система

Дизайн-система — отдельный "продукт" (свой репозиторий, публикуется как npm-пакет), поэтому это цепочка из нескольких solution, а не одно:

| # | Solution | Статус | Заметки |
|---|----------|--------|---------|
| 12 | **Дизайн-система: структура** | Решено (подход) | Отдельный репозиторий, отдельный от основного monorepo, публикуется как npm-пакет |
| 13 | **Дизайн-система: токены и theming поверх Angular Material** | Open | Цвета/spacing/typography, кастомизация theming Material |
| 14 | **Дизайн-система: компонентный слой** | Open | Правила: когда оборачиваем существующий Material-компонент, когда пишем с нуля |
| 15 | **Применение дизайн-системы в приложении** | Open | Как потребитель (платформа/встраиваемое приложение) подключает и использует npm-пакет дизайн-системы |

## 8. Тестирование

| # | Solution | Статус | Заметки |
|---|----------|--------|---------|
| 18 | **Тестирование** | Open, требует пересмотра | Ранее Karma+Jasmine, затем переход на Jest. **Важно**: по актуальным данным официальным новым дефолтным test runner для Angular стал **Vitest** (не Jest) — начиная с Angular 21 Vitest заменил Karma как runner по умолчанию, есть встроенная схема миграции `ng generate @angular/core:karma-to-vitest`. Стоит перепроверить выбор Jest vs Vitest перед фиксацией ADR |
