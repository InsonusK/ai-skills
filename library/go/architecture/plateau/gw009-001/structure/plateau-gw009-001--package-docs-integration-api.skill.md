The service's own published contract — one proto file for grpc and for its HTTP form — the OpenAPI spec generated from it, and the package that embeds the spec into the binary.

# Core Principles
The folder is the contract: a consumer copies it, the binary embeds it, a reviewer reads it. Its rules are those of `api-develop` and `api-develop-in-go`.

# Structure
## Repository place
```
docs/
  integration/
    api/
      linkcheck/
```
## Package Structure
```
docs/integration/api/linkcheck/
  linkcheck.proto          ← hand-written: the contract; // version: 1.0.0, package linkcheck.v1
  linkcheck.swagger.json   ← generated by make proto-gen; committed
  embed.go                 ← package linkcheck, exports Spec
```

## Directory and file skills
| Directory\|file | Description | Pattern skill |
| --------------- | ----------- | -------------- |
| linkcheck.proto | The contract of both transports: `LinkCheckService` with `Check` and `RecentChecks`, each with its `google.api.http` annotation (`POST /v1/links/check`, `GET /v1/links/recent`) | — |
| linkcheck.swagger.json | The OpenAPI 2 spec `protoc-gen-openapiv2` writes; never edited | — |
| embed.go | `//go:embed linkcheck.swagger.json` into `Spec []byte` | — |

# Allowed Dependencies
- Standard library (`embed`)

# Rules
MUST:
- `linkcheck.proto` is the only hand-written contract file; `linkcheck.swagger.json` is regenerated by `make proto-gen`, never edited, renamed, or moved.
- The proto file's first line is `// version: {major}.{minor}.{patch}`, equal to the `info.version` of its `openapiv2_swagger` option; the version is bumped in every change of the file.
- The proto file lies directly in this folder — no version folder; the major is in `package linkcheck.v1;`.
- Every `rpc` carries a `google.api.http` annotation equal to its route in `contractRoutes()`.
- No hand-written `openapi.json` lives beside the generated spec.
