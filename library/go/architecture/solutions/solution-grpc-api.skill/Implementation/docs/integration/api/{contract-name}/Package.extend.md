# Goals
- Describe the grpc API and its HTTP form in one hand-written file, and generate everything else from it.

# Structure

## Package Structure
```
docs/integration/api/{contract-name}/
  {file}.proto           ← hand-written: the contract
  {file}.swagger.json    ← generated by make proto-gen; committed
  embed.go               ← //go:embed {file}.swagger.json
  openapi.json           ← deleted
```

# Implementation changes

`{file}.proto`:
```protobuf
// version: 1.0.0
syntax = "proto3";

package {name}.v1;

import "google/api/annotations.proto";
import "protoc-gen-openapiv2/options/annotations.proto";

option go_package = "{module-path}/gen/api/{contract-name}";
option (grpc.gateway.protoc_gen_openapiv2.options.openapiv2_swagger) = {
  info: {
    title: "{title}"
    version: "1.0.0"
  }
};

service {Service} {
  // {Method} mirrors the domain service's own method.
  rpc {Method}({Method}Request) returns ({Method}Response) {
    option (google.api.http) = {
      post: "/v1/{resource}"
      body: "*"
    };
  }
}

message {Method}Request {
  string input = 1;
}

message {Method}Response {
}
```

`embed.go` — the `//go:embed` line names the generated file:
```go
//go:embed {file}.swagger.json
var Spec []byte
```

# Rule changes

## MUST
- Take the version, the path, and the fields of the proto file from the `openapi.json` it replaces, and delete `openapi.json` in the same change.
  - Violation: `openapi.json` left beside `{file}.swagger.json`; a route that was `POST /v1/links/check` annotated as `post: "/v1/check"`; `info.version` restarted at `1.0.0` for a contract published as `1.3.0`.
  - Risk: two specs of one contract; a path or a field changed by the move is a breaking change of a published major that no one decided.
  - Fix: one `google.api.http` annotation per former path item, the same field names (lowerCamelCase in JSON is the proto field's snake_case), the same version; the baseline's HTTP API feature must pass unchanged.
- Never nest the proto file under a version folder; the major is in `package {name}.v{major};`.
  - Violation: `docs/integration/api/{contract-name}/v1/{file}.proto`.
  - Risk: `paths=source_relative` then writes the Go code to `gen/api/{contract-name}/v1/` — another import path than `go_package` declares — and the spec to a folder `embed.go` is not in.
  - Fix: the proto file directly in the contract's folder.
- Give a method whose success is not 200 its status in an `openapiv2_operation` `responses` annotation.
  - Risk: the generated spec lists 200 for every method, and the handler that rightly answers 201 or 202 contradicts it.
  - Fix: annotate the method; the handler writes the same status.

# Check list
- [ ] The folder holds `{file}.proto`, `{file}.swagger.json`, and `embed.go`, and nothing else.
- [ ] The first line of `{file}.proto` is `// version: {major}.{minor}.{patch}`, equal to the spec's `info.version`, its major equal to the package's `v{major}` and the routes' `/v{major}/`.
- [ ] Every `rpc` has a `google.api.http` annotation.
