# Problem
The HTTP form of a proto contract must answer the same operations, statuses, and JSON as the Go and dotnet services of the same contract (skill api-develop, ADR `http-form-by-routes-over-generated-messages` of `vp-http-api-in-dotnet`). FastAPI binds request and response types it can describe as pydantic models; the generated protobuf messages are not pydantic models.

# Selected variant
[[#Routes over the generated messages]]

# Searched variants

## Routes over the generated messages

**Selected.**

### Description
`pipeline/proto.py` holds `decode_proto(request, message)` - `json_format.ParseDict` with unknown fields ignored, its errors raised as `KindError` of kind invalid - `proto_json(message, status)` - `MessageToDict`, lowerCamelCase, defaults left out - and `unimplemented(message)`. A route takes the `Request` and its path parameters by the spec's names (`Path(alias="listId")`) and returns the `Response`. `make proto-gen` runs grpcio-tools' `protoc` with the release binary of `protoc-gen-openapiv2`.

### Benefits
- The JSON is protobuf's own mapping, the one grpc-gateway, Go's `protojson`, and dotnet's `JsonFormatter` write; the spec is byte for byte the Go example's.
- The command layer and the gRPC entry point see one set of types; no second model to keep in step with the proto file.

### Costs
- FastAPI neither validates nor describes the body: a body that is not the message is answered by `decode_proto`, and the spec is not FastAPI's.
- One binary outside Python, downloaded by `make proto-gen` for the platform; four vendored proto files.

## Pydantic models generated from the proto file

### Description
A generator such as `protobuf-to-pydantic` writes a pydantic model per message; the routes bind them as in the hand-written mode.

### Benefits
- FastAPI binds and validates as in the hand-written mode.

### Costs
- A second generated type per message, mapped to the protobuf message for the gRPC form or to the command; the generator's JSON (proto names, `null`, defaults written) is not proto-JSON unless configured per field.
- FastAPI's spec would still differ from the protoc-gen-openapiv2 spec of the other stacks.

## Pydantic models written by hand

### Description
The hand-written mode's models, kept equal to the proto messages by review.

### Benefits
- No new code in the pipeline.

### Costs
- Two descriptions of one message, which drift; the contract scenario sees the routes, not the shapes.
