# Goal
- **The gRPC client variation point in Python** - A Python application that keeps every property of [vp-grpc-client](library/architecture/spec/vp-grpc-client.skill/vp-grpc-client.skill.md) and [api-client](library/develop/core/api-client.skill/api-client.skill.md), in the packages of [app-layers-in-python](library/develop/python/app-layers-in-python.skill.md); this skill details their implementation for Python and restates none of their rules.
- **Attached by the listed changes only** - Attaching it adds packages and files and changes only the base files [attach.allow](./attach.allow) names, which the repository's attach check verifies against [base-plateau-in-python](library/architecture/python/base-plateau-in-python.skill/base-plateau-in-python.skill.md)'s example.

# Core Principle
- **Copied once, generated per contract, written per method** - `infrastructure/client/core/` is copied from templates and never edited; per API the application copies its `.proto`, generates `src/{package}/gen/client/{api-name}`, and writes a client package whose methods are calls of the generated stub over `GrpcClient.channel`, its mock, and the service over it.
- **The service is the HTTP client's** - The service catches only the outcomes of `core/outcomes.py`, the same for an HTTP and a gRPC client ([httpx2-and-one-outcome-module](library/architecture/python/vp-http-client-in-python.skill/adr/httpx2-and-one-outcome-module.md)): the service, its errors, the command, and their scenarios are those of [vp-http-client-in-python](library/architecture/python/vp-http-client-in-python.skill/vp-http-client-in-python.skill.md), file for file.

```
docs/integration/client/{api-name}/{name}.proto   the provider's contract, copied unchanged
src/{package}/gen/client/{api-name}/              make proto-gen: _pb2, _pb2_grpc, and their .pyi; never edited
src/{package}/infrastructure/client/
├── core/                    copied from templates, never edited
│   ├── outcomes.py          ApiUnavailableError, ApiStatusError, StatusCode - the HTTP client's file
│   └── grpcclient/          config.py: load_config(prefix): {API}_HOST, _GRPC_PORT, _TLS, _TIMEOUT; MOCK
│                            client.py: GrpcClient.open - a lazy channel, or the emulator's server; _CallInterceptor
│                            features/ test/ - the fixed code's scenarios, with an echo API of their own
└── {api}/                   written per API (todo_api)
    ├── {api}.py             PREFIX, METHODS, the client with one method per method, open_api(config, logger), new(logger)
    ├── mock/{api}_mock.py   emulator(server): the generated servicer implemented with stable data ({API}_HOST=mock)
    └── features/ test/      each method against a server of the scenario + the two contract scenarios
```

# Rule

## MUST

### Copy the client code from templates
Copy [infrastructure/client/core/](./templates/src/{package}/infrastructure/client/core/) to `src/{package}/infrastructure/client/core/`, with the example's `grpcclient/features/` and `grpcclient/test/`, replacing `{package}` with the import name of the package, and add `grpcio==1.84.0` and `protobuf==7.36.2` to the dependencies and `grpcio-tools==1.84.0`, `mypy-protobuf==5.1.0`, and `types-grpcio==1.84.0.20260928` to the dev dependencies of `pyproject.toml`. With the HTTP client attached too, `outcomes.py` and `core/__init__.py` are already there, unchanged.
- Risk: a retyped client drifts in its deadline, its outcomes, or its log from every other Python client of the catalog.
- Fix: copy the files; after filling, searching them for `{package}` returns nothing; `make test` and `make lint` pass.

### Generate the consumed contract with proto-gen
Add the example's `proto-gen` target to the `Makefile`: it maps each folder of `docs/integration/client/` to the import path `{package}.gen.client.{api-name}` (`-I{package}/gen/client/{api-name}=docs/integration/client/{api-name}`), so the generated modules import each other there and the copy stays unchanged; run `make proto-gen` and commit `src/{package}/gen/client/`.
- Violation: the generated code edited, or generated into `gen/api/`, where the gRPC API's own contracts go.
- Risk: a consumed contract and a served one of the same package overwrite each other's generated modules.
- Fix: with the gRPC API attached too, `proto-gen` runs both loops, `gen/api/` and `gen/client/`.

### One client package per API
Write each API as `src/{package}/infrastructure/client/{api}/` holding `PREFIX` (`"TODO_API"`), `METHODS` (the full name of every method it calls), `open_api(config, logger)` and `new(logger)`, both async, a client class with `aclose()` over the generated stub, and per method one method that calls the stub and maps the response to the client's own dataclasses.

```python
async def plan_items(self, titles: list[str]) -> list[Item]:
    """ItemsService.PlanItems: one open item per title, planned by the API."""
    answer = await self._items.PlanItems(todo_pb2.PlanItemsRequest(titles=titles))
    return [Item(title=item.title, done=item.done) for item in answer.items]
```

- Violation: `grpc.aio.insecure_channel` in the client; a generated message returned to the service; a method missing from `METHODS`.
- Risk: a channel that bypasses `GrpcClient.open` has no deadline, no log, and no request id; the contract scenario misses the method.
- Fix: follow the example's [todo_api.py](./examples/src/todo/infrastructure/client/todo_api/todo_api.py); the gRPC client keeps the names the HTTP client uses (`Item`, `plan_items`), so the service over it does not change with the transport.

### Answer every method in the mock
Write the mock of each client as `src/{package}/infrastructure/client/{api}/mock/{api}_mock.py` with `emulator(server: grpc.aio.Server)` adding a servicer of the generated base that answers every method of `METHODS` as the API does, with stable data and no state, aborting with the API's status where it answers one; `{API}_HOST=mock` serves it on a `grpc.aio` server inside the process, on a port of the loopback, which the same channel reaches.
- Risk: a method the servicer does not write answers `UNIMPLEMENTED` under `mock`, and the service cannot run without the other service.
- Fix: the mocked scenario of the client's feature runs it and checks its answer.

### Build the client and the service in main.py
Build the client with `await {api}.new(logger)` in `# [services]` of `main.py`, stopping the start with "startup failed" on its `ValueError`, build the service over it, pass the service to `build_handlers`, and close the client when `run_all` returns, as [vp-http-client-in-python](library/architecture/python/vp-http-client-in-python.skill/vp-http-client-in-python.skill.md) does.
- Risk: a mocked client never closed leaves its emulator's server running when the loop ends.
- Fix: one client per API, built and closed by the composition root.

### Cover the client with scenarios
Copy the example's `grpcclient/features/` and `grpcclient/test/` unchanged but for the package: they cover the settings, the call, the outcomes, the log, and the mock through an echo API of their own, described by a generic handler over `google.protobuf.StringValue`. Write per client a feature calling each method against a `grpc.aio` server of the scenario and its emulator mocked, and its two contract scenarios: `METHODS` against the copied `.proto` compiled now with `grpc_tools.protoc --descriptor_set_out`, and the descriptor of the generated module against that compiled file, without the `json_name` compilers derive; take the service's and the command's scenarios from the HTTP client; tag them `@type/tech-check` and `@type/service`.
- Risk: a client feature that repeats the outcomes of the interceptor grows with every method and tests nothing new.
- Fix: a client feature checks only its own request and mapping.

# Check list
- [ ] `src/{package}/infrastructure/client/core/` is a filled copy of the templates; no placeholder is left.
- [ ] The consumed `.proto` is unchanged under `docs/integration/client/{api-name}/`; `src/{package}/gen/client/{api-name}` is generated by `make proto-gen`.
- [ ] Each API has its package with `PREFIX`, `METHODS`, `open_api`, `new`, a client with `aclose` and one method per method, and `mock/{api}_mock.py`; both contract scenarios pass.
- [ ] The service, its errors, the command, and their scenarios are those of the HTTP client.
- [ ] `main.py` awaits the client, builds the service in `# [services]`, and closes the client after `run_all`.
- [ ] `make test` and `make lint` pass; `bash test/check-vp-attach.sh` in this repository reports no base file changed beyond [attach.allow](./attach.allow).
