# Goal
- **The gRPC variation point in Python** - A Python application that keeps every property of [vp-grpc-api](library/architecture/spec/vp-grpc-api.skill/vp-grpc-api.skill.md); this skill details that skill's implementation for Python and restates none of its rules.
- **Attached by the listed changes only** - Attaching it adds files and changes only the base files [attach.allow](./attach.allow) names, which the repository's attach check verifies against [base-plateau-in-python](library/architecture/python/base-plateau-in-python.skill/base-plateau-in-python.skill.md)'s example.

# Core Principle
- **Copied once, written per command** - `pipeline/` and the fixed middleware are copied from templates and never edited; per command the application writes, in its service's module of `endpoint/`, a handler, a method of the servicer, and its `decode` and `encode`.
- **One chain of plain middleware** - grpcio's `grpc.aio` server runs every unary call through one chain of async functions of the call and `call_next` — the call log, the answer of failures, then the application's interceptors — so a middleware sees the request, the response, and the exception, as Go's interceptor does ([ADR](./adr/grpcio-aio-with-a-chain-of-middleware.md)).

```
docs/integration/api/{contract-name}/{file}.proto   the contract, written by hand
src/{package}/gen/api/{contract-name}/              generated by make proto-gen, committed (ADR)
│   {file}_pb2.py  {file}_pb2_grpc.py  + .pyi       messages, servicer, client, their type stubs
src/{package}/api/
├── core/rpcstatus/          copied (error-kinds-in-python): kind → google.rpc.Code; the same in every network entry point
└── grpc/
    ├── pipeline/            copied, never edited
    │   ├── config.py        GRPC_LISTEN_PORT, GRPC_REFLECTION_ENABLED
    │   ├── call.py          call(handler, request, decode, encode)
    │   └── server.py        Service, Server: the chain, reflection, graceful stop; run()
    ├── middleware/          the shape of a middleware, one package per middleware
    │   ├── interceptor.py   copied: IncomingCall, CallNext, Interceptor
    │   ├── call_log/        copied, fixed, outermost: CallLogMiddleware, x-request-id
    │   ├── answer_failures/ copied, fixed: AnswerFailuresMiddleware, status_of
    │   └── {name}/          an application's {Name}Middleware, given in entry()'s list
    ├── endpoint/            one module per proto service: {Service}Handler with service()
    └── services.py          Endpoints with from_handlers, services(), entry()
```

# Rule

## MUST

### Copy the entry point from templates
Copy [api/grpc/pipeline/](./templates/src/{package}/api/grpc/pipeline/) and [api/grpc/middleware/](./templates/src/{package}/api/grpc/middleware/) and, from [error-kinds-in-python](library/develop/python/error-kinds-in-python.skill/error-kinds-in-python.skill.md), `api/core/rpcstatus/` unless another entry point already put it there, with the example's `features/` and `test/` of each, replacing `{package}` with the import name of the package.
- Risk: a retyped server answers some error `UNKNOWN` with the exception's text, or drifts in its logging or shutdown from every other Python service of the catalog.
- Fix: copy the templates; after filling, searching them for `{package}` returns nothing; `make test` passes.

### Add the gRPC packages
Add `grpcio==1.84.0`, `grpcio-reflection==1.84.0`, and `protobuf==7.36.2` to the dependencies and `grpcio-tools==1.84.0`, `mypy-protobuf==5.1.0`, `types-grpcio==1.84.0.20260928`, `types-grpcio-reflection==1.0.0.20260508`, and `types-protobuf==7.35.1.20260906` to the dev dependencies of `pyproject.toml`, and the marker `type/api/grpc` to its pytest markers.
- Risk: an unpinned generator writes different code on another machine; generated code newer than the installed `grpcio` or `protobuf` refuses to import.
- Fix: the generators are dev dependencies of the project, run from its virtual environment by `make proto-gen`.

### Write the contract and generate its code
Write `docs/integration/api/{contract-name}/{file}.proto` as [todo.proto](./examples/docs/integration/api/todo/todo.proto) shows — `// version:` first, `package {name}.v{major};` — per [api-develop](library/common-workflow/develop/api-develop.skill/api-develop.skill.md), and generate `src/{package}/gen/api/{contract-name}/` with the `proto-gen` target of the example's [Makefile](./examples/Makefile), which maps each contract folder to the import path of its package ([ADR](./adr/generated-code-inside-the-package.md)).

```make
proto-gen:
	for dir in docs/integration/api/*/; do \
		contract=$$(basename $$dir); \
		mkdir -p src/todo/gen/api/$$contract; \
		touch src/todo/gen/__init__.py src/todo/gen/api/__init__.py src/todo/gen/api/$$contract/__init__.py; \
		$(PYTHON) -m grpc_tools.protoc \
			-Itodo/gen/api/$$contract=$$dir \
			--plugin=protoc-gen-mypy=$(VENV)/bin/protoc-gen-mypy \
			--plugin=protoc-gen-mypy_grpc=$(VENV)/bin/protoc-gen-mypy_grpc \
			--python_out=src --grpc_python_out=src \
			--mypy_out=src --mypy_grpc_out=src \
			$$dir*.proto; \
	done
```

- Violation: message classes written by hand; generated files edited or not committed; `import todo_pb2` fixed by hand in a generated file.
- Risk: the server and its clients disagree on the wire format; a generated module that imports its sibling by a bare name fails to import once installed.
- Fix: replace `todo` in the target with the package's import name; run `make proto-gen` after every proto change and commit the result with its `.pyi` stubs.

### One module per service in the endpoint package
Write each service of the proto contract as `api/grpc/endpoint/{service}.py` holding a `{Service}Handler` class with one command handler per method, a `from_handlers(handlers)` classmethod taking them from the command registry, and a `service()` method returning `Service(name, add_to)`; beside it a servicer subclassing the generated `{Service}Servicer` with one `async` method per rpc that returns `await call(handler, request, decode, encode)`, and a `decode` and an `encode` per method.

```python
class _ItemsServicer(todo_pb2_grpc.ItemsServiceServicer):
    def __init__(self, handler: ItemsHandler) -> None:
        self._handler = handler

    async def PlanItems(self, request: todo_pb2.PlanItemsRequest, context: grpc.aio.ServicerContext[Any, Any]) -> todo_pb2.PlanItemsResponse:
        return await call(self._handler.plan_items, request, decode_plan_items, encode_plan_items)


def decode_plan_items(request: todo_pb2.PlanItemsRequest) -> PlanItemsCommand:
    return PlanItemsCommand(titles=list(request.titles))
```

- Violation: a method that catches a `KindError` or calls `context.abort` itself; a generated message passed to a command; a service's methods written in `pipeline/`.
- Risk: an error answered in a method answers differently from every other; the command layer depends on the transport; a method added to the proto file and forgotten here answers `UNIMPLEMENTED` in production.
- Fix: `decode` raises `ValueError` for a request that cannot become the command, `call` answers it `INVALID_ARGUMENT`; every other error propagates to the chain. The generated stub declares the servicer's methods abstract, so a missing method fails `make lint` with "cannot instantiate abstract class".

### Register the services in services.py
List every service as a field of `Endpoints`, its line in `Endpoints.from_handlers`, and its `service()` in `services()` of `api/grpc/services.py`, beside `entry(handlers, logger, interceptors)`, the entry factory, and nothing else there.
- Risk: a service missing from `services()` is served by no one, and its every call answers `UNIMPLEMENTED`.
- Fix: one field and one line per service; the contract scenario compares `services()` with the services of the generated descriptors.

### Replace the startup entry in main.py
Replace the startup `Entry` in `# [entries]` of `main.py` with `grpc_api.entry(handlers, logger, interceptors)`, given the command registry and the list of interceptors — empty until a variation point adds one, as [base-plateau-extension-in-python](library/architecture/python/base-plateau-extension-in-python.skill/base-plateau-extension-in-python.skill.md) describes — and delete `api/startup/`.

```python
# [entries]
ended_by = await run_all(
    logger,
    stopping,
    # the gRPC API: its calls wrapped by these interceptors, the first the
    # outermost, inside the call log
    grpc_api.entry(handlers, logger, []),
)
return exit_code(ended_by)
```

- Risk: a second way of starting the server bypasses the runner of the entry points and its exit code.
- Fix: `from todo.api import grpc as grpc_api` — the package name `grpc` is the transport's, so it is imported under that alias; inside it, `import grpc` is the library.

### Keep the fixed middleware inside the server
Let `Server.build()` put its fixed middleware, built from the logger `grpc_api.entry` gives it — `CallLogMiddleware` first, then `AnswerFailuresMiddleware` — before the list of `entry` in the one chain of every unary call, as [fixed-middleware-inside-the-entry](library/architecture/spec/base-plateau-extension.skill/adr/fixed-middleware-inside-the-entry.md) requires.

```python
# api/grpc/pipeline/server.py, Server.build
chain: list[Interceptor] = [CallLogMiddleware(self._logger), AnswerFailuresMiddleware(self._logger), *self._interceptors]
```

- Violation: `CallLogMiddleware` or `AnswerFailuresMiddleware` given in `grpc_api.entry`'s list; an interceptor of the list that calls `context.abort` with a status of its own.
- Risk: a call an interceptor rejects is answered `UNKNOWN` with the exception's text, or goes unlogged.
- Fix: an interceptor rejects a call by raising a `KindError`; the scenarios of `interceptor.feature` and `call.feature` hold the order, the rejection, and a crash.

### Cover the entry point with scenarios
Copy the example's `api/grpc/pipeline/features/` and `test/`: they cover the fixed code through the real server on a free port and a test service of their own (`test.v1.EchoService` with `StringValue` messages) — the error mapping, a crash, the call log and the request id, the interceptors in their order and a call one rejects, reflection on and off, the settings, and the stop with a call in flight. In `api/grpc/endpoint/` write one feature per service, calling it through the generated client with its handlers faked, and the contract scenario; tag them `@type/api/grpc` and `@type/tech-check`.
- Risk: a variation point without scenarios lets a change of the error mapping or the shutdown reach production unnoticed; a service feature that repeats the error mapping grows with every service and tests nothing new.
- Fix: a service feature checks only its own decoding and encoding, with a fake class per command recording what it received; `make test` passes.

## SHOULD

### Serve a new command in its service's module
Serve a further command of an existing service by adding its rpc and messages to the proto file, running `make proto-gen`, and adding its handler, its line of `from_handlers`, its servicer method, and its `decode` and `encode` to the service's module in `endpoint/`, and its scenario to the service's feature; the command itself joins the command registry; `main.py` does not change. A new service adds its module and feature, one field of `Endpoints`, one line each of `from_handlers` and `services()`, and one row of the contract scenario.

### Answer a deprecated rpc as unimplemented
Raise `KindError(Kind.UNIMPLEMENTED, "{Rpc} is deprecated since {version}")` from the servicer method of an rpc marked `option deprecated = true`, calling no command; its HTTP form answers 501 with the same message.

# Check list
- [ ] `api/grpc/pipeline/`, `api/grpc/middleware/` (but an application's own middleware), and `api/core/rpcstatus/` are filled copies of the templates; no placeholder is left.
- [ ] `docs/integration/api/{contract-name}/{file}.proto` is versioned per api-develop; `make proto-gen` leaves no diff; the generators are pinned dev dependencies.
- [ ] Each proto service has its module in `endpoint/` with its `{Service}Handler`, `from_handlers`, `service()`, a servicer subclassing the generated one, and per method its `decode` and `encode`; `services.py` holds only `Endpoints`, `services`, and `entry`.
- [ ] The `# [entries]` list of `main.py` has `grpc_api.entry(handlers, logger, [...])`; `api/startup/` is deleted.
- [ ] `make test` and `make lint` pass; `bash test/check-vp-attach.sh` in this repository reports no base file changed beyond [attach.allow](./attach.allow).
