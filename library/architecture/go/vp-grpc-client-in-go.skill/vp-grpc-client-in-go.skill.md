# Goal
- **The gRPC client variation point in Go** - A Go application that keeps every property of [vp-grpc-client](library/architecture/spec/vp-grpc-client.skill/vp-grpc-client.skill.md) and [api-client](library/develop/core/api-client.skill/api-client.skill.md); this skill details their implementation for Go and restates none of their rules.
- **Attached by the listed changes only** - Attaching it adds files and changes only the base files [attach.allow](./attach.allow) names, which the repository's attach check verifies against [base-plateau-in-go](library/architecture/go/base-plateau-in-go.skill/base-plateau-in-go.skill.md)'s example.

# Core Principle
- **Copied once, generated per contract, written per method** - `internal/infrastructure/client/core/grpcclient` is copied from templates and never edited; per API the application copies its `.proto`, generates `gen/client/{api-name}`, and writes a client package whose methods are calls of the generated stub over `grpcclient.Client`, the client's emulator, and the service over it.
- **The service sees outcomes, never a transport** - The service catches `outcome.ErrUnavailable` and `*outcome.StatusError`, the same for an HTTP and a gRPC client, as dotnet's `Client.Abstractions` and Python's `outcomes.py`: the service, its interface, and its scenarios are the same over both transports.

```
docs/integration/client/{api-name}/{name}.proto   the provider's contract, copied unchanged
buf.gen.client.yaml                                the consumed contracts as one input; managed mode sets go_package
gen/client/{api-name}/                             make proto-gen: messages + stub, never edited
internal/infrastructure/
├── client/                  every client of another service's API, and nothing else
│   ├── core/outcome/     copied from templates, never edited: ErrUnavailable, StatusError, Code - every transport
│   ├── core/pipeline/    copied from templates, never edited: the client middleware around the attempts of a call
│   ├── core/grpcclient/     copied from templates, never edited
│   │   ├── config.go        LoadConfig(prefix): {API}_HOST, _GRPC_PORT, _TLS, _TIMEOUT; Mock
│   │   ├── client.go        New(cfg, logger, emulator) *Client: lazy connection, the interceptor; returns the outcomes
│   │   └── features/ test/  the fixed code's scenarios, with a test API of their own
│   └── {api}/               written per API (todoapi)
│       ├── {api}.go         Prefix, Methods, Client with one method per method and its own types, Close
│       ├── mock/{api}_mock.go   mock.Emulator: the generated server implemented with stable data ({API}_HOST=mock)
│       └── features/ test/  each method against a gRPC server of the scenario + the contract scenarios
└── {store}/                 a store (memory, postgres): beside client/, never in it
internal/service/{name}.go   the service over the client: technical outcomes → the application's kinds
```

# Rule

## MUST

### Copy the client code from templates
Fill and copy [config.go](./templates/internal/infrastructure/client/core/grpcclient/config.go) and [client.go](./templates/internal/infrastructure/client/core/grpcclient/client.go) to `internal/infrastructure/client/core/grpcclient/`, with the example's `features/` and `test/`, [outcome.go](./templates/internal/infrastructure/client/core/outcome/outcome.go) to `internal/infrastructure/client/core/outcome/`, and [pipeline.go](./templates/internal/infrastructure/client/core/pipeline/pipeline.go) with the example's `features/` and `test/` to `internal/infrastructure/client/core/pipeline/` — already there, unchanged, when the HTTP client is attached — replacing `{module-path}` with the module path from `go.mod`, and add `google.golang.org/grpc` to `go.mod`.
- Risk: a retyped client drifts in its timeout, its error report, or its log from every other Go client of the catalog.
- Fix: copy the files; after filling, searching them for `{module-path}` returns nothing; `make test` passes.

### Generate the consumed contract with buf
Add the tool lines of `buf`, `protoc-gen-go`, and `protoc-gen-go-grpc` to `go.mod`, and `buf.gen.client.yaml` with `docs/integration/client` as its input and per consumed contract a `go_package` override in its managed mode, as the example's [buf.gen.client.yaml](./examples/buf.gen.client.yaml) does; run `make proto-gen` and commit `gen/client/`. The input needs no `buf.yaml`.

```yaml
managed:
  enabled: true
  override:
    - file_option: go_package
      path: todo                                    # the folder of the contract under docs/integration/client
      value: github.com/example/todo/gen/client/todo
```

- Violation: `go_package` edited in the copied `.proto`; a `go_package_prefix` override, which names the package after the proto package (`todov1`) and not its folder.
- Risk: the copy no longer is the provider's file, or the generated package's name differs from its folder in every import.
- Fix: one override line per contract; with the gRPC API attached too, its `buf.yaml` and `buf.gen.yaml` keep generating the API's own contracts, and `make proto-gen` runs both templates.

### One client package per API
Write each API as `internal/infrastructure/client/{api}/` holding `Prefix` (`"TODO_API"`), `Methods` (a `grpcclient.Method` - the generated `..._FullMethodName` and `Retryable` - for every method it calls), `New(logger, middlewares)` reading the settings and `NewClient(cfg, logger, middlewares)` taking them, `Close`, and per method one method of `Client` that calls the generated stub and maps its response to the client's own types.

```go
// PlanItems is ItemsService.PlanItems: one open item per title, planned by the API.
func (c *Client) PlanItems(ctx context.Context, titles []string) ([]Item, error) {
	answer, err := c.items.PlanItems(ctx, &todo.PlanItemsRequest{Titles: titles})
	if err != nil {
		return nil, err
	}
	items := make([]Item, len(answer.GetItems()))
	for i, item := range answer.GetItems() {
		items[i] = Item{Title: item.GetTitle(), Done: item.GetDone()}
	}
	return items, nil
}
```

- Violation: `grpc.NewClient` called in the client; a generated message returned to the service; a method missing from `Methods`.
- Risk: a connection that bypasses `grpcclient.New` has no timeout, no log, and no request id; the contract scenario misses the method.
- Fix: follow the example's [todoapi.go](./examples/internal/infrastructure/client/todoapi/todoapi.go); a new method adds its method, its line of `Methods`, and its method in [todoapi_mock.go](./examples/internal/infrastructure/client/todoapi/mock/todoapi_mock.go).

### Answer every method in the mock
Write the mock of each client as `internal/infrastructure/client/{api}/mock/{api}_mock.go`, package `mock`, with `Emulator(grpc.ServiceRegistrar)` registering an implementation of the generated server, embedding its `Unimplemented...Server`, that answers every method of `Methods` as the API does, with stable data and no state, and pass it to `grpcclient.New`; `{API}_HOST=mock` serves it over `bufconn` inside the process. The file's name says it is a mock and of which client.
- Risk: a method the emulator does not write answers `UNIMPLEMENTED` under `mock`, and the service cannot run without the other service.
- Fix: the emulator's scenario runs the client mocked and checks its answer.

### Map the outcomes in the service
Write the service over the client in `internal/service/` with an unexported interface of the client's methods it uses, turning `outcome.ErrUnavailable` into `entity.ErrUnavailable`, each `*outcome.StatusError` code it expects into an error of the kind that fits, and anything else into an error with no kind, wrapping the client's error with `%v`, never `%w`, where it carries a kind of its own.

```go
var status *outcome.StatusError
switch {
case errors.Is(err, outcome.ErrUnavailable):
	return nil, fmt.Errorf("%w: the todo service: %v", entity.ErrUnavailable, err)
case errors.As(err, &status) && status.Code == outcome.CodeInvalidArgument:
	return nil, fmt.Errorf("%w: the todo service rejected the titles: %s", entity.ErrInvalid, status.Message)
case err != nil:
	return nil, fmt.Errorf("the todo service: %w", err)
}
```

- Violation: an entity built from the API's answer whose error is wrapped with `%w`.
- Risk: an item the other service got wrong is answered to this service's client as its own invalid input.
- Fix: the scenario "Any other answer is a failure with no kind" of the example's `remote_planner.feature`.

### Build the client and the service in main.go
Build the client with `{api}.New(logger, middlewares)` in `// [services]` of `cmd/{app}/main.go`, stopping the start with its error, close it with `defer`, build the service over it, and pass the service to `command.NewHandlers`. Build the client middleware of the API in `// [client middleware]` before it - empty until a variation point (`vp-client-retry`) adds one - and pass it to `{api}.New(logger, middlewares)`, which hands the client's `Methods` and the list to `grpcclient.New`; the client refuses a call of an operation not in `Methods`, and `Retryable` on a `grpcclient.Method` marks one safe to repeat, as [api-client](library/develop/core/api-client.skill/api-client.skill.md) requires.

```go
// [services]
todoAPI, err := todoapi.New(logger, clientMiddlewares)
if err != nil {
	logger.Error("startup failed", "error", err)
	return 1
}
defer todoAPI.Close()
remotePlanner := service.NewRemotePlanner(todoAPI)
```

- Risk: a connection never closed holds its streams until the process ends, and a mocked one its emulator.
- Fix: the command takes the service through an interface; the composition root builds and closes the client.

### Cover the client with scenarios
Copy the example's `internal/infrastructure/client/core/grpcclient/features/` and `test/` unchanged but for the module path: they cover the settings, the call, the outcomes, the log, and the mock through a test API of their own, described by a hand-written `grpc.ServiceDesc`. Write per client a feature calling each method against a gRPC server of the scenario and its emulator mocked, and its two contract scenarios: `Methods` against the copied `.proto` compiled with `github.com/bufbuild/protocompile`, and the generated descriptor against that compiled file without its options; per service a feature with the client faked; tag them `@type/tech-check` and `@type/service`.
- Risk: a client feature that repeats the outcomes of the interceptor grows with every method and tests nothing new.
- Fix: a client feature checks only its own request and mapping.

# Check list
- [ ] `internal/infrastructure/client/core/grpcclient/{config,client}.go` are filled copies of the templates; no placeholder is left.
- [ ] The consumed `.proto` is unchanged under `docs/integration/client/{api-name}/`; `gen/client/{api-name}` is generated by `make proto-gen` with a `go_package` override.
- [ ] Each API has its package with `Prefix`, `Methods`, `New`, `NewClient`, `Close`, and one method per method, and its mock in `mock/{api}_mock.go`; both contract scenarios pass.
- [ ] The service maps `outcome.ErrUnavailable`, the expected `outcome.StatusError` codes, and nothing else to kinds; it is the same over HTTP and gRPC.
- [ ] `main.go` builds the client middleware of each API in `// [client middleware]`; every operation of the client is in its list, `Retryable` where a repeat does what one call does.
- [ ] `main.go` builds and closes the client and builds the service in `// [services]`.
- [ ] `make test` passes; `bash test/check-vp-attach.sh` in this repository reports no base file changed beyond [attach.allow](./attach.allow).
