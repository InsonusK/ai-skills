# todo

The base plateau in dotnet with the gRPC API, its HTTP form, and the PostgreSQL variation point
attached: one proto contract (`docs/integration/api/todo/todo.proto`) served over gRPC on :9090 and
over HTTP on :8080, the lists of items kept in PostgreSQL through EF Core, which maps the list
aggregate of the domain itself, the schema in migrations generated by `dotnet ef`. The application
needs a database:

| rpc | HTTP | Shows |
|---|---|---|
| `PlanItems` | `POST /v1/items/plan` | no database |
| `AddItem` | `POST /v1/lists/{listId}/items` | the list loaded, an item added, the list saved; a title already in the list answers 409 |
| `ListItems` | `GET /v1/lists/{listId}/items` | the list read with its items; an unknown list answers 404 |
| `ClearList` | `POST /v1/lists/{listId}/clear` | a deprecated method: 501 / `UNIMPLEMENTED` |

```bash
curl -X POST localhost:8080/v1/lists/home/items -H 'Content-Type: application/json' -d '{"title":"buy milk"}'   # 201
curl localhost:8080/v1/lists/home/items                                                                        # 200
grpcurl -plaintext -d '{"listId":"home"}' localhost:9090 todo.v1.ItemsService/ListItems
```

```bash
export DATABASE_DSN='Host=localhost;Database=todo;Username=todo;Password=todo'
make init                          # once: the packages and dotnet ef
make migrate                       # bring the database up to the latest migration
make run                           # serve gRPC on :9090 and HTTP on :8080 (Swagger UI at /swagger/)
make migration NAME=AddItemDueDate # a migration from the changed mapping; needs no database
make proto-gen                     # regenerate todo.swagger.json after editing the proto file
TEST_DATABASE_DSN='Host=localhost;Username=postgres' make test   # every scenario, each on a database of its own
```

| Setting | Default | Meaning |
|---|---|---|
| `DATABASE_DSN` | required | the database, a connection string of Npgsql |
| `MIGRATE_ON_START` | `false` | apply the migrations before the entry points start: only for a deployment pinned to one instance |
| `TEST_DATABASE_DSN` | required by `make test` | the PostgreSQL the scenarios create and drop their databases on |

| Project | Layer |
|---|---|
| `src/App/App.Host` | composition root (`Program.cs`), the entry points (`Api/Grpc`, `Api/Http`), base settings |
| `src/App/App.Migrate` | the migration job, `/app/migrate` of the image |
| `src/Modules/Todo/Todo.Commands` | the commands and their results — all an entry point sees |
| `src/Modules/Todo/Todo.Application` | the command handlers, each over `IRepository<ItemList>` |
| `src/Modules/Todo/Todo.Domain` | entities (the aggregate `ItemList` and its items), specifications, domain services, the rule errors |
| `src/Infrastructure/Postgres/Postgres` | `AppDbContext`, `Configurations/` (the mapping of each module's entities), `Repositories/`, `PostgresFailures`, `Migrations/`, settings |
| `src/Infrastructure/Postgres/Postgres.Testing` | the database of one scenario |
| `src/Infrastructure/Memory/Memory` | `MemoryRepository<T>`: the same contract in memory, for the handlers' scenarios |
| `src/Middleware/StoreFailures` | the command middleware that tells a failure of the database in the error kinds |
| `src/Shared` | the error kinds, and `Persistence/` — the repository's contract (`IRepository<T>`, `IAggregateRoot`, `IStoreFailures`) |
| `src/BuildingBlocks` | fixed code |
| `third_party/proto` | the googleapis and openapiv2 annotations the proto file imports |

Every `{Project}.Tests` sits beside the project it tests.
