# Problem
The job must end with an exit code, run in the image with no SDK, and be coverable by a scenario.

# Selected variant
[[#An executable project]]
- Chosen by the owner (2026-10-31).

# Searched variants

## An executable project

**Selected.**

### Description
`App.Migrate` reads `DATABASE_DSN`, calls `PostgresMigrations.ApplyAsync`, logs, and exits 0 or 1. `dotnet ef` is a local tool used only for generating.

### Benefits
- No SDK or `dotnet-ef` at run time; its scenarios run in `make test`.

### Costs
- One more small project in the solution and the image.

## A migration bundle

### Description
`dotnet ef migrations bundle` builds the executable.

### Benefits
- No code of ours.

### Costs
- The image build depends on `dotnet-ef`; its behaviour is outside the scenarios.

## SQL files and DbUp

### Description
Hand-written `.sql` files applied by DbUp.

### Benefits
- The same files could serve every stack.

### Costs
- The schema and EF Core's model are kept apart and can drift; nothing generates a migration.
