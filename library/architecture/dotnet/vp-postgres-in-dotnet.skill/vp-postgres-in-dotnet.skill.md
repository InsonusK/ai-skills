# Goal
- **The PostgreSQL variation point in dotnet** - A dotnet application that keeps every property of [vp-postgres](library/architecture/spec/vp-postgres.skill/vp-postgres.skill.md); this skill details its implementation for dotnet and restates none of its rules.
- **Attached by the listed changes only** - Attaching it replaces the in-memory store of [vp-http-api-in-dotnet](library/architecture/dotnet/vp-http-api-in-dotnet.skill/vp-http-api-in-dotnet.skill.md)'s proto example and changes only the files [attach.allow](./attach.allow) names, which the repository's attach check verifies.

# Core Principle
- **EF Core behind hand-written stores** - One `AppDbContext`, a row class per table, a store per table; the service keeps its methods. Decision recorded in [stores-over-ef-core](./adr/stores-over-ef-core.md).
- **A store calls SaveChangesAsync** - So the duplicate key reaches the service. Decision recorded in [a-store-saves-at-once](./adr/a-store-saves-at-once.md).
- **One scope per command** - `ScopedSender` gives a command and its nested commands one context. Decision recorded in [one-scope-per-command](./adr/one-scope-per-command.md).

```
src/
├── BuildingBlocks/Pipeline/ScopedSender.cs     copied: AddCommandScope, one scope per command
├── App/App.Migrate/                            copied: the job, /app/migrate of the image
└── Infrastructure/Postgres/
    ├── Postgres.Abstractions/
    │   ├── StoreExceptions.cs                  copied: DuplicateKeyException, StoreUnavailableException
    │   └── I{Table}Store.cs                    per table: the store's interface and its row record
    ├── Postgres/
    │   ├── AppDbContext.cs, AppDbContextFactory.cs, PostgresConfig.cs, PostgresModule.cs,
    │   │   PostgresMigrations.cs, StoreFailures.cs     copied
    │   ├── Rows/{Thing}Row.cs                  per table: the row and its IEntityTypeConfiguration
    │   ├── Stores/Postgres{Thing}Store.cs      per table
    │   └── Migrations/                         generated: make migration NAME=...
    ├── Postgres.Testing/TestDatabase.cs        copied: one database per scenario
    └── Postgres.Tests/
```

# Rule

## MUST

### Copy the fixed code from templates
Copy [templates/src](./templates/src/), with `dotnet-tools.json` of the example to `.config/`, add the projects to the solution, the package versions of the example's `Directory.Packages.props` (`Microsoft.Extensions.*` raised to EF Core's version, EF Core pinned), and the Makefile targets `migrate` and `migration`.
- Violation: a second `DbContext` per module; a `DbSet` property edited into `AppDbContext`; `App.Host` referencing `Postgres` from anything but `Program.cs`.
- Risk: two contexts mean two migration histories over one database; a retyped `StoreFailures` reads an error code in several places.
- Fix: a table adds its row, its configuration, its store, and its migration; no fixed file changes.

### Register the database and the command scope
Load `PostgresConfig.Load()` in the `try` of `AppConfig.Load()`, call `AddPostgres` and register each store `Scoped` in `// [services]`, call `AddCommandScope()` after every `Add{Module}Module()`, register each service over a store `Scoped`, and turn `ValidateScopes` on.

```csharp
// [services]
services.AddPostgres(postgres);
services.AddScoped<IListStore, PostgresListStore>();

// [handlers]
services.AddTodoModule();          // .AddScoped<IItemLists, ItemListsService>()
services.AddCommandScope();

// before the entries
await using var provider = services.BuildServiceProvider(new ServiceProviderOptions { ValidateScopes = true });
if (postgres.MigrateOnStart) { await PostgresMigrations.ApplyAsync(postgres, stopping); } // in a try: a failure logs "startup failed", exit 1
```

- Violation: `AddSingleton<IItemLists, ItemListsService>` over a scoped store; an entry point resolving `IMediator`; a handler running nested commands with `Task.WhenAll`.
- Risk: a singleton keeps one context for every command, which fails under the first concurrent calls; `IMediator` from the root skips the scope; a context serves one call at a time.
- Fix: everything over the context is scoped; entries and handlers take `ISender`; nested commands run one after another.

### Write a row and its configuration per table
Declare a `{Thing}Row` class in `Postgres/Rows/` with its `IEntityTypeConfiguration`, naming the table, columns, and indexes in snake_case explicitly, with a unique index for every rule of uniqueness.

```csharp
row.ToTable("list_items");
row.Property(item => item.ListId).HasColumnName("list_id");
row.HasIndex(item => new { item.ListId, item.Title }).IsUnique().HasDatabaseName("list_items_list_id_title_key");
```

- Violation: a domain entity mapped; a `[Table]` attribute; uniqueness checked with a select before the insert only.
- Risk: the domain depends on EF Core; two concurrent inserts both pass a check that has no index behind it.
- Fix: the index is the rule; the store reports its violation.

### Write a store that saves at once
Let each write of a store add to `context.Set<TRow>()`, call `SaveChangesAsync`, and on failure detach the row and throw the store's outcome by `StoreFailures`; let each read use `AsNoTracking` and select into the store's row record.

```csharp
context.Set<ItemRow>().Add(item);
try
{
    await context.SaveChangesAsync(cancellationToken);
}
catch (Exception error) when (StoreFailures.IsDuplicateKey(error))
{
    context.Entry(item).State = EntityState.Detached;
    throw new DuplicateKeyException($"duplicate key: list \"{listId}\", title \"{row.Title}\"", error);
}
catch (Exception error) when (StoreFailures.IsUnavailable(error))
{
    context.Entry(item).State = EntityState.Detached;
    throw new StoreUnavailableException($"insert into list \"{listId}\": the database does not answer", error);
}
```

- Violation: a store returning `IQueryable`; a row left tracked after a failed save; `ExecuteUpdate`, `ExecuteDelete`, or raw SQL for a write.
- Risk: a query built above the store depends on EF Core; a failed row is sent again by the next save of the command; a write past `SaveChanges` is outside the unit of work.
- Fix: materialize inside the store; detach on failure; write through the tracker. A bulk statement needs a decision of its own in the unit of work.

### Generate every migration
Change the row, run `make migration NAME={What}`, read what it wrote, and commit it with the row; apply with `make migrate` locally and with `App.Migrate` in a deployment, publishing it beside `App.Host` so the image has `/app/migrate`.
- Violation: a `HasPendingModelChanges` scenario removed; a migration edited after it was applied somewhere; `EnsureCreated`.
- Risk: the model and the schema drift, and `MigrateAsync` stops the deployment; `EnsureCreated` leaves no history.
- Fix: a new migration for every further change. Decision recorded in [migration-job-as-a-project](./adr/migration-job-as-a-project.md).

### Give the health variation point its check
With [vp-health-in-dotnet](library/architecture/dotnet/vp-health-in-dotnet.skill/vp-health-in-dotnet.skill.md) attached, pass the check of `AspNetCore.HealthChecks.NpgSql`, its package added to `App.Host`.

```csharp
services.AddManagement(new ReadinessCheck("database", new NpgSqlHealthCheck(new NpgSqlHealthCheckOptions(postgres.Dsn))));
```

- Violation: a readiness check that sends a command.
- Risk: a check through a command fails on a business rule and holds traffic back for nothing.
- Fix: the check opens a connection of its own. The proto example has no health entry, so this line is not in it; the check runs in `Postgres.Tests`, on a database that answers and on one that does not.

### Create the database of each scenario
Create a `TestDatabase` per scenario, apply `PostgresMigrations.ApplyAsync` where the scenario needs the schema, and dispose it after the scenario.
- Violation: `TestDatabase` in a static field; `DisableTestParallelization` removed from a project whose scenarios set the environment.
- Risk: scenarios see each other's rows.
- Fix: the database is created in a step and dropped in `[AfterScenario]`; the DSN of `TEST_DATABASE_DSN` needs `CREATEDB`.

# Check list
- [ ] The fixed files are unchanged copies of the templates; one `AppDbContext`, one migration history.
- [ ] Stores and the services over them are scoped; `AddCommandScope()` follows every module; `ValidateScopes` is on.
- [ ] Each store saves at once, detaches a failed row, and reports through `StoreFailures`; reads use `AsNoTracking`; no store returns `IQueryable`.
- [ ] Every uniqueness rule has a unique index; names are snake_case.
- [ ] Every change of a row has its generated migration; the scenario on `HasPendingModelChanges` passes.
- [ ] `App.Migrate` is published as `/app/migrate`; `MIGRATE_ON_START` stays `false` beyond one instance.
- [ ] `make test` passes with `TEST_DATABASE_DSN` set; `bash test/check-vp-attach.sh` in this repository reports no file changed beyond [attach.allow](./attach.allow).
